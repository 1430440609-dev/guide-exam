# Guide exam website maintenance

- The user wants GitHub Pages at one permanent public repository URL. Do not publish updates to the earlier ChatGPT Sites host.
- Keep the current visual design and features when adding questions. Answer feedback belongs inline below the choices; never show an answer dialog.
- Use compact quick previous/next tap buttons above the options; the user replaced swipe navigation after real-phone failures. Preserve vertical scrolling and zoom.
- Keep independent saved sessions per practice mode and filter context. Switching modes/filters, reload and reopen resume the exact question, current round, submitted answers, random order and unsubmitted multiselect draft; switching must never start a new round or inflate counts. Each mode also remembers its own filters. First-time sessions hide lifetime historical answers; only the explicit restart-set button starts another full round. Keep lifetime latest records separate from round answers.
- Restart repeats the same snapshot, including wrong questions already corrected in that round. Count completion only when all questions in the snapshot have been answered; never double-count reloads or single-question retries. Show current round and completed count per mode/filter context. Preserve wrong/starred/history on restart.
- Keep versioned asset URLs generated by tools/build.mjs so mobile caches cannot mix new HTML with old scripts/styles.
- Maintain a shared published bank for everyone. Personal progress, mistakes and bookmarks stay in each browser. Keep localStorage key `guide-study-v1` stable.
- Preserve all existing question IDs and order during additions. Do not rebuild the original bank with new IDs, renumber it, or replace it with an incoming document.
- `dist/bank.json` is the original 165-question bank. Append new banks to `dist/extra-banks.json`, then rebuild `dist/bank.js` with `tools/build.mjs`. The `GUIDE_BANKS` array is the shared catalog.
- Prefer `tools/add-bank.mjs --file PATH --title TITLE --python BUNDLED_PYTHON` for future additions. It accepts DOCX, JSON, or formatted text; validates answers/options, skips duplicate questions and preserves existing IDs.
- Word extraction must include text from section headers and footers. Several original choices and answers are stored there.
- Validate the original bank with `node tools/check.cjs`. Verify inline answer reveal, multiselect submit, separate visitor progress and record retention after bank append.
- `tools/package-pages.mjs` prepares the public files in `outputs/github-pages/`. Publish only that allowlisted output; never upload reference/, original Word files, local filesystem paths, credentials, or personal browser data.
- The deployed repository root contains the published copies of the app and bank files. To modify from that checkout, maintain the same invariants even if the local dist/tools authoring layout is not present.

- The current catalog has 8 papers and 1320 questions: four volumes each for subjects 1/2 and 3/4. Sixteen supplied Word files are eight question/answer pairs, not sixteen independent papers. The original volume 3 subjects 3/4 stays in dist/bank.json with vip3-1..165 IDs; do not append its paired documents again.
- For paired documents, use tools/import-vip-documents.py and tools/check-import.cjs. Restore Word automatic numbering and read section headers/footers; verify each numbered stem and options against the matched answer document. Every answer must come from an explicit reference-answer field. Record layout/OCR discrepancies and their source-based resolutions privately under reference/vip-import/. Never infer answers or change them based on general knowledge.
- Preserve subjects 1, 2, 3 and 4 in engine validation and filters. The original paper's questions 25 and 38 have source-verified subject-4 classifications; all original question IDs, answer letters and other content were retained.
